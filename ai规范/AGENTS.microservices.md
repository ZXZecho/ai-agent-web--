# 微服务 / 多模块场景的边界约定

## 1. 权限模型：全局只读，局部可写

- ✅ **可读**：整个仓库（为了理解接口定义、公共库、命名风格）。
- ✅ **可写**：只有本次任务授权的**单一服务目录**。
- ❌ **禁写**：其他所有服务、`shared-libs/`、`docker-compose.yml`、`.env*`、CI 配置。

## 2. 每次任务开头必须声明的权限块

AI 在开始前必须先把这块抄一遍并确认，然后才能动手：

```
【本次权限】
- 可写：services/notification-service/src/
- 只读：services/*/（理解接口用）、shared-libs/、docs/
- 禁写：services/order-service/、services/payment-service/、任何配置文件
- 如需越界：先停下，说明理由，等我批准
```

## 3. 分工原则

| 模式 | AI 负责 | 人负责 |
|---|---|---|
| **垂直切分（推荐）** | 低风险、非核心服务：通知、日志、报表、原型 | 核心链路：订单、支付、用户、鉴权 |
| **水平切分** | 各服务的样板代码：CRUD、DTO、单元测试骨架 | 业务逻辑、异常处理、性能优化、安全加固 |
| **工具分离** | 一套工具只开 AI 负责的目录 | 另一套工具只开人工负责的目录，双方从不互开 |

> 铁律：**AI 工具与人使用的 IDE，不要同时打开同一个服务目录。**

## 4. 跨服务调用的写法

- 需要调用其他服务的接口时：**先读对方的接口定义/文档，再由人确认**，再在授权服务内自行编写客户端代码。
- 不得修改被调用方的代码来“适配”自己；接口不一致时报告冲突，由人决定改哪边。

## 5. 通用库（shared-libs）的特殊规定

- 默认 **只读**。
- 确需修改时，必须：说明影响范围（哪些服务会受影响）→ 列出回归测试清单 → 获批准后再改 → 改完必须跑全量测试。

## 6. 公共文件禁止单独修改

以下文件任何情况下不得由 AI 单独修改，只能提出建议：

- `docker-compose.yml`、`Dockerfile`、`k8s/`、`helm/`
- `.github/workflows/`、`.gitlab-ci.yml`、Jenkinsfile
- `package.json` / `pyproject.toml` / `pom.xml` 的依赖段
- 数据库迁移脚本、初始化 SQL
- `.env`、`.env.*`、密钥文件

## 7. 升级为“人机双轨”的判断标准

出现下列任一情况，立即把任务交回人工，AI 只做建议：

- 改动会波及 2 个以上服务
- 涉及鉴权、支付、资金、隐私数据
- 涉及数据迁移或不可逆操作
- 涉及并发、事务、分布式一致性
- 现有测试覆盖不足且难以补测
