> **触发场景**：要修改已存在的代码、修 bug、优化性能、补错误处理、加安全措施时。
> **核心**：**别再让 AI「重写整个文件」**，精确指出文件 + 行号 + 问题 + 期望。

# 局部改码规范

## 一、为什么必须精确到行

| 对比 | 模糊请求 | 精确请求 |
|---|---|---|
| 表述 | 「登录接口有问题，改一下」 | 「`src/api/auth.ts` 第 45–52 行密码校验没用 bcrypt，改成 `bcrypt.compare()`」 |
| AI 行为 | 可能重写整个函数甚至整个文件 | 只改指定的 8 行 |
| 风险 | 引入意外变更、删掉必要逻辑 | 变更范围可控、易审 |
| 效率 | 多轮澄清 | 一次到位 |

## 二、标准格式

> **文件路径 + 行号范围 + 当前代码 + 问题描述 + 期望修改 + 约束**

```markdown
## 局部代码修改请求

**文件**：`src/services/user_service.ts`
**行号**：L124–L130
**当前代码**：
```ts
// 粘贴 3–10 行
```

**问题**：
1.
2.

**期望修改**：
1.
2.

**约束**：
- 保留函数名与返回值结构
- 不要修改其他行
```

## 三、常见修改类型的模板

### 修 bug

```markdown
**文件**：`src/api/order.ts`　**行号**：L87–L94
**当前代码**：
```ts
const total = items.reduce((s, i) => s + i.price * i.qty, 0)
const discount = total * 0.1
const final = total - discount
```
**问题**：折扣规则错了，应为满 100 减 10，不是固定 10%。
**期望修改**：
```ts
const discount = total >= 100 ? 10 : 0
const final = total - discount
```
**约束**：保留原有变量名。
```

### 性能优化

```markdown
**文件**：`src/utils/data_processor.ts`　**行号**：L201–L215
**问题**：嵌套查找导致 O(n²)，各 1 万条时超时。
**期望修改**：先建 Map 索引，降到 O(n)。不要改变函数签名。
```

### 补错误处理

```markdown
**文件**：`src/clients/http_client.ts`　**行号**：L67–L70
**问题**：`catch (e)` 吞掉所有异常，真实错误被隐藏。
**期望修改**：只捕获网络错误与超时，其他异常原样抛出；日志不带请求体。
```

### 安全加固

```markdown
**文件**：`src/api/admin.ts`　**行号**：L112–L118
**问题**：① 缺权限校验，任何登录用户都能删；② 未校验目标是否存在。
**期望修改**：
1. 加 `requireRole('admin')`
2. 不存在返回 404
3. 记录操作审计日志（操作人 / 目标 / 时间）
**约束**：不改 API 路径与响应格式。
```

## 五、请求改码时的禁忌写法

| ❌ 错误做法 | 问题 | ✅ 正确做法 |
|---|---|---|
| 「第 45 行有问题」 | 没说是什么问题 | 「第 45 行变量名 `data` 与全局冲突，重命名为 `localData`」 |
| 「把 bug 修一下」 | 没有现象描述 | 「输入空字符串时第 67 行抛越界，需增加空值判断」 |
| 只贴代码不给路径 | AI 不知道在哪 | 「在 `src/main.ts` 第 102–105 行」 |
| 不给当前代码 | AI 只能猜 | 粘贴 3–10 行当前代码 |
| 一次提多个不相关问题 | AI 遗漏或混淆 | 一次一个文件 / 一个函数 |
| 「改一下这个函数」 | 文件里函数很多 | 「修改 `calculateTotal`（第 120–135 行）」 |

## 六、给 AI 的强制要求

1. **只改我点名的行**；其他行的任何变动（包括格式化、空行、引号风格）都算越界。
2. 如果我的行号与实际内容对不上，**先报告不一致并贴出实际内容**，不要自作主张猜。
3. 如果你认为我还需要改别的地方，**单独列在「建议」区**，不直接动手。
4. 输出必须是最小 diff：只包含我授权范围内的 hunk。
