> **性质**：规则包自身的维护说明。AI 不必逐字读，但维护者必读。
> **最后更新**：2026-11-20

# 规则包使用与维护说明

## 一、为什么规则会失效

| 失效点 | 表现 | 本包的对应解法 |
|---|---|---|
| **没读到** | 文档藏在某个盘里，AI 从不打开 | `AGENTS.md` 每次自动加载 |
| **被淹没** | 长文档后半段被忽略；超预算被截断 | 常驻文件只留硬约束，细则移到 `.ai-rules/` 按需读 |
| **没触发** | AI 读到了但当下想不起来用 | `AGENTS.md` 第 6 节写明「什么场景读哪个文件」 |
| **无代价** | 违反了也没人拦 | 本包只到第 2 层；第 3 层靠 hook / CI / 沙箱 |

**核心心态**：不要指望 AI「自觉遵守」，要设计成「即使它不遵守也会被拦住」。

## 二、四层架构（本包覆盖前两层）

```
第1层 常驻规则   AGENTS.md（全局 + 项目）       ← 解决"读到"
第2层 细则库     .ai-rules/*.md（按需读取）     ← 解决"上下文预算"
第3层 机械拦截   hook / CI / 沙箱 / 目录隔离    ← 解决"违反有代价"（需另配）
第4层 会话仪式   开工 / 改码 / 收工 三个模板     ← 穿插在第1、2层里
```

## 三、怎么把新踩的坑加进去

AI 犯了新错时，按这个顺序处理：

1. **先判断能否机械化**：能不能用 hook、CI、lint 规则、类型系统挡住？
   - 能 → 去做第 3 层，**不要**往 `AGENTS.md` 里加（机器管的事别浪费上下文）。
   - 不能 → 继续下一步。
2. **写成一行可判定条款**：主语明确、动作可验证、有触发条件。
   - ❌ 差：「注意代码质量」
   - ✅ 好：「修改 `src/models/` 下的文件前必须先问我，即使只改注释」
3. **放到正确的层**：
   - 所有项目都会犯 → `AGENTS.global.md`
   - 只有这个项目会犯 → 项目 `AGENTS.md`
   - 需要长说明 / 模板 → `.ai-rules/` 下对应文件
4. **更新「最后更新」日期**。

## 四、季度体检清单

每季度花 10 分钟过一遍：

- [ ] `AGENTS.global.md` 是否还 ≤ 80 行？
- [ ] 有没有条款从来没被触发过？（可能是写给想象的）
- [ ] 有没有条款已经能被工具自动拦住？（删掉，降级为第 3 层）
- [ ] 项目技术栈版本号是否过时？
- [ ] 可写/禁写目录是否跟当前仓库结构对得上？
- [ ] 有没有两条条款在打架？

## 五、常见误区

| 误区 | 实际 |
|---|---|
| 把整份规范文档塞进 `AGENTS.md` | 会超预算被截断，AI 反而读到一半 |
| 规则写得像说明书 | 模型对散文的执行力远低于清单 |
| 只在项目里放规则 | 换项目就全忘了；全局层别忘了 |
| 规则越写越多 | 越多越没人执行；短才有效 |
| 觉得写了 AI 就会遵守 | 只有机械拦截是可靠保证 |

## 六、与其他文件的关系

- 长版背景知识（工具评测、完整案例）留在原文档，**不进规则包**。
- 项目实况（已实现功能、架构决策、待办）建议另建三个文件：
  - `PROJECT_CONTEXT.md` — 技术栈、目录权限、已实现清单、禁忌
  - `DECISIONS.md` — 架构决策记录（ADR）
  - `TODO.md` — 待办
- 这三个文件由 `.ai-rules/03-上下文与恢复.md` 引用。
