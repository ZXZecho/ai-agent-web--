> **触发场景**：AI 交付代码后、合并前、每次自审时。
> **核心**：AI 的代码必须像陌生人的 PR 一样审。**不审 = 没写。**

# 交付前审查清单

AI 交付时必须对照本清单逐项给结论：`通过 / 不通过 / 不适用`，并说明理由。不通过项必须修完再交付。

## 一、安全性（13 项）

- [ ] **SQL / NoSQL 注入**：是否全用参数化查询或 ORM？有无字符串拼接查询？
- [ ] **XSS**：输出到 HTML 时是否转义？有无 `dangerouslySetInnerHTML` / `v-html` 且未净化？
- [ ] **硬编码密钥**：有无 `secret = "..."`、写死的 token、写死的 IP？
- [ ] **密码哈希**：是否用 bcrypt / argon2？禁用 MD5 / SHA1 / 明文。
- [ ] **输入校验**：类型、长度、范围、格式是否全部校验？在前端还是后端（应后端）？
- [ ] **路径遍历**：文件路径是否可用 `../` 逃逸？是否限制在基目录内？
- [ ] **命令注入**：有无 `exec` / `system` / `eval` / 拼接 shell 参数？
- [ ] **不安全的反序列化**：是否用 `pickle` / 原生 `eval` 处理不可信数据？
- [ ] **日志泄露**：日志里是否出现密码、token、身份证、卡号？
- [ ] **越权**：有没有校验「这个用户是否拥有这条数据」？（水平越权最常见）
- [ ] **CORS**：生产是否 `*`？是否允许了不必要的凭据？
- [ ] **传输安全**：生产是否强制 HTTPS？是否配置 HSTS？
- [ ] **依赖漏洞**：新增依赖是否审核？有无已知高危漏洞？

## 二、逻辑正确性（10 项）

- [ ] **边界条件**：空数组 / null / 空串 / 0 / 负数 / 超大值是否处理？
- [ ] **异常处理**：是否捕获了具体异常？是否区分业务异常与系统异常？
- [ ] **事务边界**：多步写操作是否在同一事务？失败是否回滚？
- [ ] **竞态条件**：共享状态是否加锁？异步代码有无 race？
- [ ] **循环退出**：有无无限循环？是否设了最大迭代/重试次数？
- [ ] **类型转换**：有无隐式转换、精度丢失（尤其金额）？
- [ ] **资源释放**：文件 / 连接 / 流是否正确关闭（try-with-resources / using / defer）？
- [ ] **业务规则**：折扣、税费、库存扣减等是否符合约定？
- [ ] **幂等性**：重复请求是否造成重复扣款 / 重复创建？
- [ ] **分页**：大数据量接口是否分页？有无一次拉全表的查询？

## 三、性能（8 项）

- [ ] **N+1 查询**：循环里是否有查询？是否用预加载（`include` / `selectinload` / `join fetch`）？
- [ ] **索引**：查询条件字段是否有索引？是否全表扫描？
- [ ] **缓存策略**：热点数据是否缓存？过期时间是否合理？是否会导致脏读？
- [ ] **连接池**：数据库 / Redis 连接池是否配置？是否泄漏？
- [ ] **大对象**：是否返回了不必要的大字段（base64 图片、全量日志）？
- [ ] **串行改并行**：多个独立 I/O 是否可并发？
- [ ] **内存泄漏**：全局 Map / 订阅 / 定时器是否无限增长？
- [ ] **阻塞事件循环**：CPU 密集或同步 I/O 是否阻塞了异步主线程？

## 四、可维护性（9 项）

- [ ] **命名一致**：是否符合项目命名风格？
- [ ] **注释**：复杂逻辑、业务规则、hack 是否说明原因？
- [ ] **函数长度**：是否超过约 50 行、是否可拆分？
- [ ] **重复代码**：是否有可提取的重复片段？
- [ ] **导入顺序**：是否符合项目规范？
- [ ] **类型注解**：参数与返回值是否完整？
- [ ] **魔法数字**：是否提取为常量 / 配置？
- [ ] **异常类型**：是否抛出了过宽的通用异常？
- [ ] **测试覆盖**：关键路径是否有测试？测试是否有真实断言？

## 五、AI 特有风险（额外 8 项）

- [ ] **幻觉库 / API**：引用的库和函数是否真实存在、版本是否支持？
- [ ] **过时 API**：是否使用了已废弃的方法？
- [ ] **过度设计**：是否为一个简单需求造了 4 个类和 2 层抽象？（KISS / YAGNI）
- [ ] **擅自扩功能**：是否实现了我没要求的东西？
- [ ] **测试造假**：是否有 `assert true`、被 skip 的测试、被削弱的断言？
- [ ] **夹带改动**：是否顺手格式化、重命名、删除注释、升级依赖？
- [ ] **空实现**：是否有 `// TODO` 占位却声称完成？
- [ ] **时间/时区**：时间是否用 UTC 存储、展示时再转换？

## 六、交付时的固定话术

> 「对照清单逐项自查，输出格式：
>
> | 类别 | 结论 | 说明 |
> |---|---|---|
> | 安全 | 通过 / 2 项不通过 | |
> | 逻辑 | | |
> | 性能 | | |
> | 可维护 | | |
> | AI 风险 | | |
>
> 不通过项列出具体行号与修复方式；确认修完后再交付。」

## 七、人工侧的最低动作

- 只看 **diff**，不看整文件——认知负担小，异常更明显。
- 多文件改动按「数据层 → 服务层 → 路由层」顺序审。
- 合并前在干净环境跑一遍：测试、静态检查、关键路径手动验证。
- 拿不准的地方直接问 AI「这段如果输入 X 会怎样」，比读代码快。
