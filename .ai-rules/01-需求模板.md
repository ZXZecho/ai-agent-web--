> **触发场景**：我要给你派任务、描述需求、或你自己觉得需求模糊时。
> **目标**：一次说清，把返工从 3–5 次压到 0–1 次。

# 需求描述规范

## 一、标准公式

> **[角色设定] + [核心任务] + [技术栈与版本] + [输入规格] + [输出规格] + [约束条件] + [示例]**

| 要素 | 作用 | 缺了会怎样 |
|---|---|---|
| 角色设定 | 「你是资深的后端专家」→ 提高专业度 | 回答泛泛 |
| 核心任务 | 说「做什么」，不说「怎么做」 | 方向跑偏 |
| 技术栈与版本 | 语言、框架、DB、ORM、工具链 + 版本号 | 生成别的技术栈 |
| 输入规格 | 方法、路径、字段、类型、校验规则 | 接口对不上 |
| 输出规格 | 成功状态码/结构；失败错误码/消息 | 前后端联调失败 |
| 约束条件 | 安全、性能、兼容性 | 埋坑 |
| 示例 | 一个具体的请求/响应样例 | 歧义最大化 |

## 三、短格式（快速场景）

> 在 [技术栈] 下，[任务]。要求：输入 [输入格式]，输出 [输出格式]。
> 额外限制：[关键约束]。不要额外添加功能。

示例：

> 在 Vite + React 18 + TypeScript 下，实现一个 `GET /items/:id` 的列表项详情组件。
> 要求：id 为字符串，不存在时显示「未找到」。不要添加缓存、分页或自动重试。

## 四、正反对照（记住这个落差就够了）

| 场景 | ❌ 差的需求 | ✅ 好的需求 |
|---|---|---|
| 注册接口 | 「写一个注册接口」 | 「用 FastAPI + SQLAlchemy + PostgreSQL 实现注册：输入 username/email/password，密码 bcrypt，输出 user_id + token」 |
| 排序函数 | 「写个排序」 | 「`sort_numbers(list, reverse=False)`，输入整数列表输出去重后升序列表，reverse=True 降序，空列表返回 []，不改原列表」 |
| 文件读取 | 「读取文件内容」 | 「`read_config(path) -> dict` 读 JSON；文件不存在返回 {} 并记警告；JSON 非法抛 ValueError 带行号；固定 utf-8」 |
| 日期处理 | 「格式化日期」 | 「`format_iso8601(dt) -> str`，输出 UTC 的 ISO8601；naive datetime 先转 UTC」 |
| 并发下载 | 「并发下载」 | 「asyncio + aiohttp，`fetch_all(urls)`，超时 10s，最多 5 并发，失败返回 (url, 错误信息)」 |
| 加缓存 | 「加个缓存」 | 「`get_user_profile` 加 LRU，最多 100 条 / 5 分钟过期，禁止无上限全局字典」 |
| 加日志 | 「加日志」 | 「`process_payment` 加结构化日志：请求 ID、用户 ID、金额；成功 info、失败 error 带堆栈；不记卡号」 |
| 错误处理 | 「加个错误处理」 | 「订单不存在返回 404 `{"code":"NOT_FOUND"}`；DB 错误返回 500 并记日志；不暴露内部异常」 |

## 五、自检清单（发给 AI 前逐项过）

- [ ] 技术栈明确：语言、框架、数据库、版本号都写了？
- [ ] 输入输出定义：给出具体结构或函数签名？
- [ ] 异常情况：说了错误场景怎么处理？
- [ ] 约束条件：安全、性能、兼容性列了？
- [ ] 边界条件：空值、极值、重复、并发考虑了吗？
- [ ] 示例：提供了完整的输入输出样例？
- [ ] 范围限制：声明了「不要做什么」？
- [ ] 任务粒度：拆到可独立验收了吗？

> **自评**：这 8 项有任意一项你 2 分钟内答不上来，说明需求还没想清，先别发。

## 六、给 AI 的要求（写进项目 `AGENTS.md` 时用）

- 需求缺上述任一项 → 先提问，列出一张「我需要你补的信息」清单，**不许假设**。
- 收到需求后，先输出「我的理解」与「改动计划」，等我确认。
- 我发现你自行补充了没要求的功能（YAGNI 违规），我会要求全部删除。
